# Never call a 'use client' module's export from server code; the gate checks what next build may not render

Date: 2026-07-04, updated 2026-10-09   Area: frontend

**Context**: During the DS realignment, swapped a hand-rolled CTA on the waitlist page (a Server Component) to `buttonVariants({variant:'secondary'})`. tsc/eslint passed but `next build` failed at prerender: buttonVariants is a pure function but lives in the `'use client'` Button.tsx, so Next marks it a client-only export — importing it into a server component and calling it throws.

It recurred on 2026-10-09 where `next build` could not see it. The homepage example (`HeroExample`, a server component) gained an evidence row whose chip called `sourceTraceChipClass()` from the `'use client'` SourceTrace.tsx. Lint, tsc, vitest, a CI-env `next build` and e2e all passed: CI builds with no `NEXT_PUBLIC_EXAMPLE_FILING_ID`, so `/` renders the static fallback, which has no evidence row. Vercel's build reads the live example summary, rendered the row, and failed prerendering `/` on every push of PR #1148 and of the PR stacked on it. A mock API serving one located risk excerpt reproduced it locally.

**Rule**: (a) An export of a `'use client'` module is a client reference in server code: render it (`<Button>`) or pass it to a client component, never call it (`buttonVariants()`, `sourceTraceChipClass()`, `useCountUp`). A module without `'use client'` is server code when a page, layout or route reaches it through imports that never cross the directive. (b) A helper both sides need (a class recipe, a formatter) lives in a module without the directive (`features/filings/lib/sourceTraceChip.ts`), and the client component imports it from there. For a link-styled CTA in a server component, keep a token-clean `<a>` or extract a small client wrapper. (c) `next build` only checks the paths the build renders; a branch that only live data reaches (an env-gated example, a populated payload) escapes it. The static gate covers every path.

**Gated (rule 12)**: `frontend/tests/unit/serverCallsClientExport.spec.ts` walks the import graph from the App Router's server files (page, layout, route, sitemap, … without `'use client'`, plus middleware and instrumentation) through modules without the directive, follows barrel re-exports (`@/components/ui` → Button.tsx) to the module that defines a name, and fails on any call or `new` of a `'use client'` module's export. Fixtures cover a direct import, a barrel, an `export *`, a namespace, a client component rendered (allowed) and server code reached only through a client module (not server). Limits: dynamic `import()`, a client export held in a variable before the call, a shadowing local, and packages.

**Evidence**: `app/waitlist/page.tsx` + `buttonVariants({variant:'secondary'})` (2026-07); `features/marketing/components/HeroExample.tsx` + `sourceTraceChipClass()` (PR #1148, Vercel prerender error "Attempted to call sourceTraceChipClass() from the server but sourceTraceChipClass is on the client"); fixed by moving the recipe to `features/filings/lib/sourceTraceChip.ts`.
