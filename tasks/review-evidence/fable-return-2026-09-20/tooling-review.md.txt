# Independent returned-Fable tooling review

Read-only source review of supplied tools and E8 initialization/accounting/index. No supplied script, harness, judge, CLI or installer was executed. No GitHub or production operation occurred. Only independent stdlib parsing/hashing of existing local data was used. This review addresses future resume safety, not the semantic accuracy of already-delivered verdicts.

## Findings to resolve before relying on automated resume

**1. P2 — Resume accepts unbound verdicts and logs unverified packet/request hashes.** `tools/run_queue.py:24–29, 55–61` skips a saved slot solely because its first judge object looks complete; it does not establish one row, the expected identity, contract header, original row or request equality. Before a fresh call, lines 79–81 execute `packet_path` without rehashing it. Lines 91–98 compare only ticker/form/draw and write the index's declared packet/row/request hashes into the ledger. Concrete counterexample: an otherwise valid n2 SE 20-F draw 1 result copied into an n1 SE draw 1 slot is skipped and marked complete even though generated claims differ. A replaced packet from the wrong corpus with the same ticker/form/draw also passes the post-call checks. `e8_analyze.py:11–17, 19–28` takes `results[0].judge` without binding it to the indexed row and attributes it to that slot's condition/corpus. Its `reuse` mapping is loaded on line 8 but never used to verify an E2 report/verdict hash. This can silently misattribute main or duplicate results.

Refutation pass A: frozen `judge_report.check_provenance` validates the golden-set hash, uniqueness and resolvable filing identity, not the external queue's corpus/input/request hash. Two valid corpora with the same identities therefore defeat that alternative safeguard. Refutation pass B: `consolidate.py:29,36` does compare all original non-judge row fields and would reject such a KO/E3 mismatch later, but the E8 readout does not use that consolidator; even elsewhere the paid call and inaccurate execution ledger precede rejection. Required resume boundary: revalidate packet bytes and frozen checkout/assembled request, bind saved outputs to the complete expected row and judge contract, and retain first valid results. This is not evidence of a mismatch in the returned completed KO rows; parent audits those independently.

**2. P2 — E8 invocation protection is optional in the new driver.** `tools/run_queue.py:19,66–77` makes `--guard-dir` optional. `--stage` is only reporting metadata; the E8 index has no enforced guard requirement. If an operator relocates the E8 index and omits that argument, line 79 still launches the unchanged harness with inherited PATH, bypassing the shared 601 counter and latch.

Refutation pass A: the intended handoff explicitly says to provide `--guard-dir`; that documents the correct command but does not make this generic driver's E8 admission fail closed. The delivered run-stage wrappers are not included here for independent verification. Refutation pass B: the frozen harness has its own retry but no E8 programme ceiling or durable quota latch. The strong reviewed shim cannot protect calls that never reach it. Require E8 stage/index admission to refuse absent or mismatched shared guarding, or use an explicitly reviewed wrapper that cannot take the unguarded path. No actual bypass is alleged: returned E8 state is disabled and uninitialized, and no new E8 verdicts were supplied.

## Checks and limits

All **300** E8 indexed packet byte hashes match the original frozen queue, and all indexed identity/corpus/condition/order/output/main/request/row/source fields match the private map. The execution list has **160** entries in frozen order: 140 n mains and 20 duplicates (five per condition/corpus); **140** o mains are separately marked reused. No identity substitutions observed.

`build_packets.py:42–47` reproduces the frozen metrics filtering and XBRL/statement serialization inspected in 73cc's runner. Its golden hash check is real, but it does not itself verify the documented judge-code hashes, resolve all provenance or enforce input caps before writing packets. The frozen harness will reject oversized inputs before a call. Do not mistake recorded request hashes for enforcement by run_queue.

`consolidate.py` preserves original report rows and gives a supplied valid prior verdict priority; it does not rejudge. It checks prior source and non-judge row equality and slot row equality, stronger than the driver. It does not require one row per slot or fully validate per-verdict dimensions/gates/contract; imported frozen `complete_verdict` checks only error/input-complete/PASS-or-FAIL. Independent returned-result validation remains necessary.

`e8_analyze.py` is a descriptive partial readout, not the full predeclared variance analysis: it reports per-cell means/negative rates and duplicate binary verdict agreement, but no paired per-filing disagreement, filing/issuer-block bootstrap, permutation analysis or rate-range uncertainty. Its top-line main completion counts reused dictionary entries without applying complete(), and an explicit null judge can crash the error display at lines24/29. Those paths do not establish present data corruption; E8 has not started. Do not report E8 complete or infer a causal variance effect from this tool alone.

No blanket invalidation of the attested frozen environment or current completed judgments follows. Preserve existing results, disabled guard, raw evidence and missing/error identities. User's current request is review only; none of the proposed resume actions is authorized by this receipt.
