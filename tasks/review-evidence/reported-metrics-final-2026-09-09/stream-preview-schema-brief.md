# Stream preview schema mismatch — independent review, 2026-09-09

Confirmed product defect, present before #799. The final corrected #799 report contains 380 retained preview frames: 29 distinct full strings, but one identical body from `## Financials` onward. Every frame asserts that financial metrics were not disclosed, no material incremental risks were highlighted, management commentary was limited, and guidance was not disclosed. This is a legacy renderer fallback, not a conclusion supported by the v2 extraction. Counts and the offline actual-helper reproduction are retained in `work/stream-preview-schema-probe.json`.

## Evidence and two independent refutations

1. **Refutation: the stream had not yet received financial data.** In `work/reported-metric-labels/backend/app/services/openai_service.py:493–505`, `_partial_markdown_preview` repair-parses JSON and unconditionally calls `_build_structured_markdown`. That legacy builder (`app/services/ai/markdown_render.py:41` onward) expects v1 fields such as `financial_highlights`, absent from the actual v2 sections. An offline call to the actual helper with a *complete* retained final AAPL v2 object still loses the actual headline and emits the no-metrics body. Rendering the same object with explicit `schema_version=2` through `render_sections` and `sections_to_markdown` preserves its headline and Total net sales table without those absence claims. No model or network call was used. The defect therefore survives full JSON completion; it is not merely incomplete transport data.

2. **Refutation: only the evaluation collector sees this text.** The production `_request_streaming_content` at `openai_service.py:455–490` calls that helper and awaits the supplied callback. `summary_pipeline.py:726–745` creates the preview queue under `STREAM_SECTION_REVEAL`, and lines 795–806 yield its text in the existing `type: preview`, `markdown` SSE event. `frontend/features/summaries/api/summaries-api.ts:308–314` forwards this markdown to `onChunk`; `frontend/features/summaries/hooks/useSummaryGeneration.ts:160–168` places the chunk in streaming text. These are production paths, not eval-only wiring. Queue coalescing means the 380 observed callbacks are not proof that 380 distinct events reached a browser. I did not verify a current live flag or observe a live user session.

The final path differs: `openai_service.py:690–702` supplies `SUMMARY_SCHEMA_VERSION`, then calls schema-aware `render_sections`/`sections_to_markdown`. The preview method's source is byte-identical between origin/main `4ba05087a04969e0391ac4e0efcfd1b5bef99eb3` and reviewed #799 head `b36ad45433b6b2eef05d259c168b90ccfe1b9452`. Retention exposed an existing defect; it did not introduce it. A later correct final response does not make an earlier unsupported assertion safe.

## Smallest safe correction

Use the existing schema-aware renderer for *completed* v2 section values, explicitly stamped with the schema version. Preserve the current callback, preview SSE envelope, coalescing, and final response behavior. Return no preview when no substantive completed section exists; ordinary progress heartbeats can continue. Do not route an empty v2 partial through the legacy generic fallback. Correct the stale helper and legacy-builder docstrings in the same change.

**A renderer-only switch is insufficient.** `app/services/ai/json_repair.py:40–74` expressly repairs unterminated strings and missing brackets. It can promote an in-flight `"$1` prefix of `"$1,000M"` into a seemingly complete value. The existing repair API returns only repaired text, with no proof of which values were originally closed; it cannot certify preview scalar completeness. The streaming selection must therefore precede repair and retain only source-complete sections, or show a safe pending state.

A small conservative seam is a pure JSON-boundary reader at this existing preview owner: locate the top-level `sections` object using strict JSON tokens, track string escapes and nesting, and accept only section key/value pairs whose complete original JSON value has ended. Strictly `json.loads` each completed section value; synthesize only the outer container for the renderer. Never synthesize a scalar quote, number suffix, array element, or section boundary. This preserves section-by-section progress without introducing arbitrary partial financial values. If the prefix cannot be unambiguously tokenized, return no preview and keep normal progress. A bounded single scan of the already available prefix introduces no acquisition or provider call; the current helper already joins and parses that prefix at its throttle. Avoid a second independent financial renderer or final-assembly/model calls in this seam.

Required acceptance: a completed first section renders while a later section is unfinished; a split currency scalar, escaped quote, brace inside a string, partial numeric literal, and incomplete nested array never appear as completed figures; complete v2 content renders through the same shared owner as final output; missing fields produce no claims of disclosure absence. Preview collection must retain the actual chronology and its existing `summary_call_including_internal_retries`/`not_observed` association metadata.

## Boundaries and limitations

The inspected locked backend SSE and frontend contract files are unchanged. The proposed correction needs no change to their event shape or assertions, provider, schema contract, source acquisition, retry policy, or final normalization. A meaningful unlocked preview test and a single new safe-completion invariant proof should be scoped after approval; no test, formal proof, repository edit, or paid call was performed for this investigation. This report establishes renderer mismatch and the completion hazard, not whole-corpus financial quality clearance or final-provider attribution of every retained frame.
