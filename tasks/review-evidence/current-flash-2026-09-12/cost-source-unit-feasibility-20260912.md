## What the existing parser preserves

Pinned SDK `edgar/documents/document.py::Section` retains name, part/item, start/end offsets, detection method/confidence, node and optional text extractor. `Section.text()` returns flattened text and cleans boundary artifacts. Its table nodes retain rows/cells/header structure, but the application immediately reduces sections to strings; no accounting-unit-scope registry crosses this boundary. COST's target is prose, so a table-header adapter alone cannot solve it. No existing application field certifies that an MD&A unit parent applies to a generated dollar phrase.

This review read installed parser source and retained text. It did not locate/parse COST's original HTML locally; it does not claim the original target is or is not inline tagged, or that the SDK's section offsets are exact offsets into the recorded decoded HTTP representation. ## Small adapter and projection contract

1. At selected-filing section assembly, build a private immutable **source passage registry** alongside the unchanged excerpt. Each passage has an opaque code-created ID, representation hash, exact character span, canonical part/item, and exact text. Unit declarations have separate IDs/spans and a scope kind. Recognize only a narrow explicit declaration grammar at the start of a confidently identified section, preserving its exceptions verbatim. A declaration is an observed scoped text record, not permission to convert all nearby digits. Ambiguous boundaries, conflicting headers or recovered unanchored windows yield `unit_scope_unknown`.

2. Pass registry IDs and bounded passage text through the existing primary/recovery writer. For a unit-dependent guidance passage, the writer selects a source passage ID; it does not invent the unit, numeric value or header link. Code resolves the declaration from the selected passage's verified scope. Do not accept a model-supplied scope ID that could point to another section. This needs a small internal `guidance_source_selection` contract; simply adding a prompt warning leaves the observed failure mode intact. No new public response fields or SSE events are necessary: strip internal selections before the existing section projection.

3. For the first release, generate the public guidance string from the **exact selected passage plus exact unit context**. Example presentation: `Capital expenditure plan (MD&A amounts in millions, except per-share, share, percentage and warehouse-count data): [exact source passage containing $6,500]`. Prefer reproducing the declaration verbatim rather than the normalized example if exception parsing is not implemented. This corrects standalone unit loss without deriving a new dollar number or changing a quotation. Expose source attribution as existing UI permits. Do not claim the entire guidance catalog is complete or automatically certify the selected passage's future modality.

4. Use the same validated projection in `ai/markdown_render.py::_apply_structured_fallbacks` for primary, recovery, preview and final. Only project the mapped guidance slot when selection and unit scope are valid; do not touch unrelated paragraph dollars. A source selection without known units may still render a self-contained explicit-unit quote, but must not acquire the nearest arbitrary header. If no valid selection exists, no deterministic unit repair is claimed. Whether to retain authored fallback or expose uncertainty is a scoped product decision for the implementation; silently treating it as verified is not acceptable.

This first useful slice preserves source unit meaning; it does not claim a parser understands all financial English. To convert6,500 to6.5B deterministically, a later record must identify the precise monetary occurrence, its measure (capital spending), currency, scale, target period, and exceptions. A model's suggested measure can be checked against source structure where available; unrestricted English semantic binding still needs measured quality and cannot be called a deterministic certificate.

## Independent hazard refutations

**Amount collision.** A `$6,500` occurrence elsewhere could be a literal dollar amount. Refutation1: amount equality contains no section or source identity. Refutation2: even same-section equality could identify a separate event. Therefore resolve opaque passage/span IDs, never search generated dollars and pick a match.

**Per-share and counts.** Refutation1: the exact header expressly excludes per-share, share, percentages and warehouse counts. Refutation2: the target paragraph itself contains warehouse counts16/13 beside capital amounts4,228/6,500, defeating paragraph-wide multiplication. Exact quote plus exact header preserves the distinction without pretending to classify each number.

**Unit scope.** Refutation1: a preceding table header may apply only to a table, not later narrative. Refutation2: MD&A can contain local overrides, another currency, or nested exceptions; top-level Item membership alone is insufficient for numeric conversion. Initial observer should accept only explicit section-wide declarations with preserved boundaries and flag conflicting scopes. Never infer unit authority solely from proximity.

**Primary/recovery parity.** Refutation1: primary has the header and target, so more prompt context alone does not prove a repair. Refutation2: current recovery drops the target, so a model-issued span ID must be checked against the actual registry subset supplied to that request. Keep selected passage and unit context together under one budget and reject IDs not offered in that request.

**Quoted versus authored text.** Refutation1: replacing6,500 inside an alleged verbatim quotation changes the source. Refutation2: leaving a bare quoted dollar amount without a visible inherited unit can still mislead. Preserve the quotation exactly and attach unit context outside it; later typed normalized display must be labelled separately.

## Implementation recommendation

Do not open a one-line global multiplier or another unit-warning PR. The safe first correction requires the source-selection contract and common projection above, with ordinary unlocked extraction/recovery/renderer tests, one new source-selection/unit-scope invariant, and actual COST positive/negative controls after implementation. No contract-anchor edit is justified. A metadata-only registry is independently reviewable if needed, but its PR must explicitly say it does not yet correct output. This scope is larger than a formatting patch but substantially smaller and more honest than a generic financial-prose repair engine.
