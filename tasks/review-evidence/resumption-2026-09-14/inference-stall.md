# DeepSeek non-thinking inference stall — September 14, 2026

**Finding.** Between at least 19:30 UTC and a point between 21:25 and 21:36 UTC on September 14, DeepSeek accepted chat-completion requests that disable thinking (`thinking.type=disabled`, or `reasoning_effort=none`) with HTTP 200 response headers and then sent no body, streamed or not. Requests in the provider-default thinking mode completed normally throughout. Path, TLS, authentication and routing were healthy from the same runner in the same minute. Stalled requests were not billed: the balance read USD 85.56 at 19:27 UTC (before the failed assessment) and again at 20:44 UTC after 22 timed-out requests.

**What was refuted.** SDK regression: main's OpenAI 3.8.0 and the candidate 3.13.0 stalled identically ([34891591680](https://github.com/neilmac91/EarningsNerd/actions/runs/34891591680), [34894739890](https://github.com/neilmac91/EarningsNerd/actions/runs/34894739890)) with identical HTTPX2/httpcore2 2.12.0 (transport-install comparison against accepted #845). HTTP/2: httpx2 defaults to HTTP/1.1 and no `h2` package is installed. Runner egress or credential: an unauthenticated POST through the same transport was answered 401 in 0.6 s and a keyed `GET /v1/models` returned 200 in 0.5 s ([34898642117](https://github.com/neilmac91/EarningsNerd/actions/runs/34898642117)). Application code: the diagnostics use the raw SDK, and no backend file changed between the last success (#840's run, September 13 19:20 UTC) and the first stall.

**What established the cause.** Run 34898642117 (21:24 UTC): the application's exact shape (`thinking` disabled + `temperature`) received headers at 0.6 s and no body for 23 s streamed, `APITimeoutError` at 20 s plain; the bare default request completed in 0.8 s with usage 34/8. Run [34899733464](https://github.com/neilmac91/EarningsNerd/actions/runs/34899733464) (21:36 UTC): every shape completed, including the application's, in 1.1–1.5 s with usage. Nothing changed on our side between the two runs. The DeepSeek status page listed no incident for September 14 at 21:40 UTC; its documentation now states that `temperature` in thinking mode is ignored rather than rejected, which differs from the September 10 reading.

**What remains uncertain.** Whether production traffic stalled during the window is unconfirmed: the Mac's gcloud credential has expired and the Cloud Console did not render through the browser extension, so no `ai_call` log lines were read. Every production path sends the affected shape, so summaries, Copilot and Analysis were probably failing at their 75-second deadlines during the window. The #855 Copilot failure at 07:46 UTC is a different signature (the runner exited 1 immediately after preparation with `summary: null`) and does not date the stall's start.

**Evidence.** `outputs/deepseek-transport-34898642117/transport-diagnostic.json`, `outputs/deepseek-transport-34899733464/transport-diagnostic.json`, `outputs/pr861-transport-install-comparison.json`, balance run [34894732205](https://github.com/neilmac91/EarningsNerd/actions/runs/34894732205). Workflow changes: #864 (layered probes, merged `8d356f9a`), #865 (parameter matrix, merged `e3abfbe3`). Local Mac timings were unreliable because of lazy-import stalls in the venv without a fresh bytecode-cache prefix; only fresh-cache runs are cited.

**Closure.** With the exact application shape completing again, #861's single recorded paid rerun [34899891399](https://github.com/neilmac91/EarningsNerd/actions/runs/34899891399) scored and passed 18 of 18 with XBRL citations identical to accepted #845, and #867's eval-baseline [34901458363](https://github.com/neilmac91/EarningsNerd/actions/runs/34901458363) and Copilot run [34902202900](https://github.com/neilmac91/EarningsNerd/actions/runs/34902202900) passed on the same provider path. The stall did not recur across 105 inference requests between 21:36 and 22:07 UTC.
