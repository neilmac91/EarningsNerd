## Verified issues and boundaries

**Public financial values at enlarged text.** HeroExample.tsx:81-85 makes its amount/delta nowrap while :161 creates three fixed tracks. Independent Assessment A measured the painted numbers, not only element boxes: at 390px and 32px root, the first two columns overlap by about 44.9px and the next pair by about 69.9px. At 1440px the second pair still overlaps by about 8.1px. Both themes reproduce it. Preserve full labels and amounts while allowing whole metric groups to wrap. Existing [#1278](https://github.com/neilmac91/EarningsNerd/pull/1278) and [#1311](https://github.com/neilmac91/EarningsNerd/pull/1311) leave this geometry intact. Evidence: `home-200-390.json`, `home-dark-200-390.json`, and the 1440 twins. Suggested lens: adapt, then polish. Apply the user's severity rubric in the final register: this is a production unreadable-value condition with an explicit 200% trigger.

**Sticky page identity behind global chrome.** SecondaryHeader.tsx:27 and Header.tsx:82 both use top-0; the secondary row's z-40 loses to z-50. On production pricing at scrollY 500, its H1 lies at y20-48 under the global header's y0-65. Hit testing returns the global header. The same component serves dashboard and watchlist. Either offset it using the global header's measured height or make it nonsticky; validate the back and logout actions after scroll. [#1278](https://github.com/neilmac91/EarningsNerd/pull/1278)'s measured header work does not change this top-0 recipe. Evidence: `pricing-header-light.json` and dark twin. Suggested lens: layout, then polish.

**Header auth resolution shifts the page.** The known follow-up is freshly reproduced, not copied from the older review. The local home and pricing observations each record a 0.145394 non-input layout shift. The auth cluster changes from 84x36 to roughly 306x46, the desktop nav moves horizontally, and the main offset changes. Header.tsx:129-136 uses a round skeleton while the eventual guest state is two controls. Reserve the final cluster's shape while maintaining the existing loading semantics. Evidence: `performance.json` and `performance.cjs`; one fresh context per route, 1440x900 light, stored essential-only consent, seven seconds, no backend. Suggested lens: polish.

**Source sheet does not fully own pointer interaction.** FilingWorkspace.tsx:423 has z-scrim 35, its sheet is z-40, and Header.tsx:82 is z-50. The local fixture walk activated the header theme toggle while the Source sheet remained aria-modal, in both initial themes. This is an existing follow-up, reproduced today. Reconcile the shared chrome's modal ownership, preserving the documented sheet/popover hierarchy and focus return rather than adding another dialog. The floating Source launcher also covers reading lines in today's local scroll probe. Evidence: local-walk `source-header-active-*` and `source-launcher-overlap-*`; detailed coordinates belong to that walk's finding. Suggested lens: harden, then polish.

**Feedback field and choice group duplicate existing recipes.** FeedbackWidget.tsx:90-116 builds raw pressed buttons and a raw textarea. Input.tsx:62-86 already supplies the field, and SegmentedControl supplies the named single-choice group. The widget uses white/70 plus black/10 rather than the canonical white fill and token border. [#1289](https://github.com/neilmac91/EarningsNerd/pull/1289) changes raw colour residue but leaves these duplicate structures. Migrate to the current primitives, preserving the textarea ref, form behavior, guards and accessible name. Evidence: census raw-twin record and local-walk `feedback-light-390.png`, dark twin. Suggested lens: distill, then polish.

Settings lacks a main landmark in the local capture and both its source branches use div wrappers (app/dashboard/settings/page.tsx:101 and :140). Keep this route-level item in the route appendix, with its ownership checked against [#1291](https://github.com/neilmac91/EarningsNerd/pull/1291). It is not a system-wide landmark claim.

## What works

The shared Modal bounds and scrolls its panel, traps focus by the top layer, returns focus, and owns body locking. Busy Button state preserves keyboard focus; RetryButton retains query failures while retrying. These contracts should survive recipe migrations. Typography has distinct heading, data and original-filing roles; the serif is not preloaded on every route. Financial direction and status keep separate meanings, and the local contrast samples do not support a generic tertiary-ink defect.

The local walk records no active animations for Analysis under reduced motion in either theme. Source guards the success check and other global animations; the approved pop easing is not an accessibility defect merely because the detector names it. The full frontend scanner is a useful floor and did not replace visual checks.

## Limits

The seven-second local observer is a reproducible layout-stability probe. LCP/long-task values in its raw record were not collected under a controlled production benchmark and are not used to rank this review. Native Safari/Firefox, physical devices, assistive-technology speech and every offline transition were not exercised here. No broad WCAG compliance claim follows from this audit. Public production captures cannot establish authenticated production behavior; fixture state names remain attached to local evidence.

Recommended sequence: adapt the hero metric strip; layout the secondary header; harden Source sheet ownership; distill the feedback field/group; polish the auth placeholder and rerun the existing focus/reflow/contrast gates on the real affected states. Finish with polish once those concrete repairs land.
