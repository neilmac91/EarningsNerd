# Hierarchy integration boundary audit

Read-only audit against repository head `a0fea57bb981ae55f21bb3aa72146fbc19eacb20`. This supplements the [hierarchy implementation proposal](source-review-hierarchy-proposal.md); it is not a schema change or an admission decision. These are requirements for the proposed hierarchy, not defects in the current single-context schema-2 path.

| Boundary | Current behavior | Requirement before schema-3 evidence can be admitted |
| --- | --- | --- |
| Readiness wrapper | `review_evidence_inventory` routes AI prerequisites schema 2 to `ai_review_evidence_inventory`, then appends source/development bindings. | Preserve prerequisites schema 2 and the wrapper behavior. Version only the nested source inventory, including every transitive artifact before binding. |
| Durable execution binding | `acceptance_executor` freezes the complete review inventory in SQLite and compares it on later calls. `verify_review_evidence_binding` independently rebuilds it before collection or packet construction. | Recursive inventories must be canonical and stable. Test changed leaf, registry, rendered prompt, fragment, reducer and reconciliation bytes against this equality boundary. Never refresh the original binding after outputs. |
| Source versus output-review contexts | `acceptance_ai_decision` collects only final brief and reconciliation contexts, then excludes those IDs from quality/challenge review. This is correct for the current one-context-per-role contract. | A hierarchy must supply the full source-context closure: leaf, reducer, synthesis, reconciliation-leaf and retired/failed attempts. Reusing any of those IDs for output review must fail. Add integration cases for a non-root leaf ID and a retired source ID. |
| Blinded reference packets | `build_blinded_packets` copies final `material_issues` and general readiness limitations; it does not copy per-reference `coverage_limits` or a transitive issue ledger. Decision validation checks the copied material issues. | Define a minimal blinded projection of accumulated source limitations and the evidence/issue references quality and challenge reviewers need. Hash-bind and verify it at decision time. Keep model identities, arm/configuration, custody paths and ordering private. Do not lose leaf/reducer limits during packet construction. |
| Final issue shape | `_material_issues` requires the existing nine fields exactly. Downstream packet and evaluation code consumes that list. | Keep final per-filing `material_issues` in that shape and bind origin/unit/fragment/disposition metadata in a separate schema-3 ledger. Leaf nodes may use a declared richer shape. Test the linkage rather than widening every consumer. |
| Freeze chronology and prompt rendering | The current top-level protocol freeze follows completed source briefs; schema-3 manifests and node-kind contracts must exist before their node runs. | Give manifests/contracts their own frozen identities and chronology. Verify deterministic template rendering against declared node inputs; a matching template label beside arbitrary prompt bytes is insufficient. Preserve the distinction between provider-exposed identity and an unavailable internal model build. |

The narrow code tranche therefore includes protocol/inventory validation, a shared source-context-closure helper consumed by the decision path, and the minimal blinded projection needed to retain limitations. Generator budget, acceptance thresholds, fixed accession/output identities, the Fable contract and the two denied proof holds remain outside this change.

Compatibility tests must preserve schema-2 inventory bytes and ordinary single-context decisions; reject a source leaf reused for output review; reject edited transitive evidence after execution binding; and reject omitted or altered projected coverage limits. These supplement the proposal's eight acceptance cases and need no model call or change to a denied spend/brief guard.

Capacity acceptance is separate. `acceptance_source_view.py` rejects a single raw source above 64 MiB, but that admission limit is not a measured memory or model-context guarantee, and its structural JSON can exceed the raw HTML size. Do not project the previously measured 974 MB submission collection into one process or context. Pilot bounded construction and actual leaf/reducer input sizes on H01/H02/H25, retain every structured/visual route from the document map, and stop on unsupported or oversized units. Splitting does not permit dropping unselected exhibits, hidden facts or graphics.
