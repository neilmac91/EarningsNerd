# E7 hierarchy: next implementation contract

**Status:** implementation proposal only. The hierarchy is not approved, implemented or frozen.

## Scope and compatibility

This tranche adds custody for multi-context source review; it does not judge sources, dispatch reviews, change the five protocol roles, or alter the top-level `ai_assisted` prerequisites shape.

Keep protocol schema 3 and the evidence-schema-2 path unchanged; add evidence schema 3 for a role using multiple contexts. Roles may differ in evidence version, so frozen H29 A can remain schema 2 while a fresh B uses schema 3. Do not relabel either prior artifact: compacted B remains ineligible. Reconciliation must be schema 3 when either input is schema 3; otherwise schema 2 remains valid. Inventory output becomes schema 3 only when it contains schema-3 evidence.

Primary entry points are `_context_receipt`, `validate_ai_prerequisites` and `ai_review_evidence_inventory`; add versioned brief keys plus manifest, node, ledger and schema-3 reconciliation validators. Keep each `source_briefs` row as the single final role brief, preserving the 60-brief/30-reconciliation shape. Because inventory is a consumer contract, audit `acceptance_readiness.py` inventory/binding functions, `acceptance_executor.py` seal/equality checks, and protocol, readiness, output and AI-decision integration fixtures before fixing the file set. Schema-2 inventories must remain byte-for-byte stable.

## Immutable evidence and context rules

A schema-3 brief names one `coverage_manifest` reference and an ordered `review_nodes` list. The manifest is frozen before review and contains:

- every approved source packet as `(role, sha256, byte_length)` and every complete-submission member as `(member_id, ordinal, declared_name, encoded_sha256, decoded_sha256, byte_length, disposition)`;
- leaf units with `unit_id`, `parent_id`, packet identity, ordered half-open `coverage_spans`, optional `context_spans`, `unit_sha256`, structural kind and registrant scope; and
- expected counts and IDs for tables, inline-XBRL facts including hidden facts, images, and encoded/archive members.

`unit_id` hashes canonical accession, packet identity, ordered span sets, unit hash, kind and registrant scope. `unit_sha256` hashes only length-framed `coverage_spans`; the validator recomputes both. Coverage spans partition each governed packet without gaps or overlaps. Hashed `context_spans` may repeat caption, header or footnote bytes supplied for comprehension, but never count toward coverage totals. Member dispositions are reviewed content, hash-proven exact duplicate, source-proven non-content packaging, or unresolved; unresolved holds completion.

Each node has one actual context ID, receipt and artifact hash. Source-reference kinds are `leaf`, `reducer` and `role_synthesis`; reconciliation may add `source_reconciliation_leaf`. A leaf binds one unit, a reducer the complete ordered child `(node_id, sha256)` set, and synthesis every root child. Context IDs are unique across A, B and reconciliation; only the manifest may be shared between A and B review artifacts. An append-only registry records accession, role, node, attempt and status. Compacted, truncated, failed or retired IDs cannot become eligible. Freshness is proved only against that registry and inventory, never provider-globally.

Keep the protocol-3 five-role shape, but make each role's frozen contract declare the allowed node kinds and a hash-bound prompt/template reference for each. Every node receipt binds that role contract hash, node-kind template hash, exact rendered-prompt artifact/hash, and the effective provider, model and provider-exposed version. The validator requires the tuple to match the frozen role declaration and the node kind to be allowed; an unavailable immutable build is recorded as an explicit exposure limit, never inferred. The inventory transitively freezes the contract, templates and rendered prompt bytes, so a node cannot use an undeclared alternate prompt or model.

Leaf receipts bind node/manifest/unit hashes, exact input spans and the IDs/hashes actually supplied as text, structured data or images; reducer receipts bind ordered child hashes. All retain empty candidate inputs, `source_only: true`, no truncation and no observed compaction. Every expected modality ID needs one terminal disposition. Material images require image input hashes and visual dispositions; hidden XBRL facts remain counted, and encoded members require decoded inventory/hash linkage.

A table group includes caption, headers, row/column relationships, continuations and associated footnotes. If too large for one leaf, fragments share `table_id` and consecutive ordinals: coverage remains disjoint while reusable headers/footnotes are hashed context spans. A table reducer receives every fragment and one complete logical caption/header/footnote set. Missing or unattached footnotes hold completion; repeated context is not duplicate coverage.

## Lossless propagation and fail-closed behavior

Every leaf issue has a stable ID namespaced by `unit_id` and retains source packet/hash, unit ID/hash, locator, amounts/bases, qualifiers and disclosure limits. It also carries one or more `evidence_fragments`: exact fragment payloads bound to source role/hash, half-open span and fragment SHA-256, plus structural context such as section path, table/caption/header/row/column/footnote IDs, XBRL context/unit/decimals/hidden status, or image hash and visual observation. The validator recomputes fragment hashes against the governed source or hash-bound view and confirms that the payload and structural labels were inputs to the leaf context. Raw locators and paraphrases alone are not source evidence.

Each non-leaf node records the exact union of child issue identities and one disposition per incoming issue: `supported` maps to a current-node issue ID; `rejected` retains the original issue and a source-backed reason; `unresolved` remains live and blocks complete status. A source-free reducer may resolve a conflict only from sufficient carried fragments. Otherwise it preserves the conflict as unresolved. Source-based resolution then requires a fresh, bounded `source_reconciliation_leaf` context binding the conflict history, exact source spans/fragments and a receipt; its result is added without erasing either original claim. If that bounded evidence remains insufficient, the conflict stays unresolved. A successor manifest revision is required when new source spans must enter custody.

Disagreements are similarly append-only records linking all participating issue IDs, status, resolution basis and resulting issue ID, if any. The validator checks set equality, not counts: no child issue, rejection or disagreement may disappear, and every supported mapping must target an extant parent issue. Coverage limits are accumulated as a de-duplicated union at every reducer; an empty final limit cannot erase a child limit.

Compaction or truncation invalidates that context and every dependent node. The attempt stays ineligible. A custody retry uses a new context, the same frozen role contract/model request and complete original unit or child set; eligible children may be reused. Completed and adverse findings remain in attempt history, and the replacement dispositions every prior finding. Failed-context findings are not eligible source evidence, so an adverse finding absent from the replacement remains unresolved until eligible fragments support or reject it. Never rerun an eligible substantive review to seek a more favorable outcome; a new ID or manifest does not authorize that. A legitimate correction requires a documented input/method defect, a new frozen contract/manifest as applicable, the unchanged acceptance bar, all prior findings, and explicit comparability limits. These rules exclude prior H29 B despite the later reread.

The final per-role synthesis receives child review artifacts, issue/disagreement ledgers, modality dispositions, evidence fragments and manifest identities, rather than the full source. The per-filing reconciler receives the two final brief hashes and their complete ledgers/fragments, also without the full source. For a schema-2 input, the validator deterministically normalizes its extant material issues into a read-only `legacy_unfragmented` ledger whose origin is that brief's context; it invents no fragments or rejected issues. Such an issue can be carried unchanged, but it cannot support fresh source-based conflict resolution without a bounded reconciliation leaf. The reconciler may merge adequately supported chains, preserve rejections, and expose disagreements; where the carried evidence does not support resolution, it must return unresolved rather than infer from absent source. Schema-3 reconciliation therefore adds `source_issue_ledger_sha256` beside `source_brief_sha256`, binds both in its receipt, and validates the full two-role issue/disagreement union. This keeps source evidence and limits available without claiming that a source-free reducer reread the filing.

`ai_review_evidence_inventory` must freeze the manifest, context and attempt-history registries, every leaf/reducer/synthesis/reconciliation-leaf artifact and receipt, evidence fragments, both issue ledgers, and the schema-3 reconciliation inputs. Any missing reference, hash mismatch, incomplete modality, coverage gap/overlap, reused/retired context, compaction, dropped union member, or unresolved item prevents `coverage_status: complete` and withholds the accession freeze.

## Acceptance cases

1. **Valid mixed-version H29:** frozen schema-2 A plus a fresh schema-3 B hierarchy validates; schema-3 reconciliation binds both brief hashes and normalized A/B issue ledgers. The prior compacted B ID appears only as retired and is never admitted.
2. **Coverage identity mutation:** deleting or overlapping a `coverage_span`, counting an overlapping `context_span` as coverage, or changing a packet byte length, unit hash or member disposition fails before issue validation.
3. **Context custody mutation:** reuse of a context, reuse of a retired context, compaction/truncation, or a mismatched provider/model/version, role-contract, template or rendered-prompt hash invalidates the node and every dependent node in the evidence graph.
4. **Table and modality mutation:** disjoint table fragments may reuse hashed header/footnote `context_spans`; omission of a continuation, logical caption/footnote bundle, hidden fact, image visual disposition or decoded-member linkage prevents complete coverage.
5. **Issue-union mutation:** dropping a rejected child issue, mapping a supported disposition to a missing parent issue, or omitting one side of a disagreement fails exact-set validation.
6. **Reducer retry:** a compacted reducer and its dependent nodes are rejected; a fresh context over the identical child-hash list may succeed without rerunning eligible leaves only when attempt history and every prior adverse-finding disposition remain frozen. A changed prompt or scope is rejected as a retry.
7. **Evidence-limit preservation:** a source-free reducer can resolve from hash/span-bound fragments with sufficient table or XBRL context. A locator/paraphrase-only or `legacy_unfragmented` conflict stays unresolved until a fresh bounded reconciliation leaf reads the source and retains both claim histories.
8. **Legacy isolation:** an unchanged, valid schema-2 single-context pair follows the old path byte-for-byte; adding hierarchy-only fields to schema 2 or using multiple contexts under schema 2 fails closed.
