# Alert signal source map — offline review 2026-09-22

This receipt maps the two log policies to source-owned emissions. It is an offline code audit, not a Cloud Logging query or delivery test. Cloud Run assigns `cloud_run_revision` to service logs and `cloud_run_job` to job logs; see [Cloud Run logging](https://docs.cloud.google.com/run/docs/logging). The filters search both `jsonPayload.message` (the service's [structured formatter](../../../backend/app/services/logging_service.py)) and `textPayload` (job scripts' `logging.basicConfig` output). The phrases are specific enough to omit a severity predicate while job text severity remains unverified in live readback. [Cloud Logging's filter syntax](https://docs.cloud.google.com/logging/docs/view/logging-query-language) supports the field-scoped substring checks used here.

| Generation-failure phrase | Python log level | Emitter and terminal meaning |
| --- | --- | --- |
| `Error in streaming summary` | ERROR | [`summary_pipeline.py`](../../../backend/app/services/summary_pipeline.py) catches an uncaught stream exception, then yields `error`. |
| `Pipeline timeout after` | WARNING | The same pipeline catches its hard timeout, then yields `error`. |
| `Structured extraction error` | ERROR | [`openai_service.py`](../../../backend/app/services/openai_service.py) catches extraction failure and returns `status=error`; the pipeline consumes that status without raising. |
| `drain terminal=error` | WARNING | [`summary_generation_service.py`](../../../backend/app/services/summary_generation_service.py) logs the terminal event consumed by a background/pregenerate drain. The caller can continue or classify from the Summary row. |
| `Filing not found during stream generation` | WARNING | The pipeline warns and immediately yields `error`. |
| `Error fetching SEC document` | ERROR | The pipeline logs an unrecoverable primary-document fetch error and immediately yields `error`. |
| `refresh-stale: regeneration failed for filing` | WARNING | [`summary_refresh.py`](../../../backend/app/services/summary_refresh.py) catches an exception from one in-place regeneration and counts it as failed. |
| `refresh-stale: generation ended in a terminal error for filing` | WARNING | The same refresh loop receives an `error` event, not an exception, and counts the paid attempt as failed. |

Generation scope is the `earningsnerd-backend` service plus `earningsnerd-pregenerate` job. [`pregenerate_examples.py`](../../../backend/scripts/pregenerate_examples.py) calls `precompute_one`, which calls `generate_summary_background`; [`refresh_stale_summaries.py`](../../../backend/scripts/refresh_stale_summaries.py) runs on that same job image with `--args` and calls the same drain. Scan, digest and other scheduled jobs do not call this generator in their declared entrypoints. Partial-result warnings such as `AI summarization timed out ... Switching to fallback` and `6-K exhibit extraction failed` are deliberately excluded: those paths may still complete after a fallback.

The SEC alert matches only the singleton `sec_edgar` breaker’s [`opened after` (ERROR) and `reopened after` (WARNING) emissions](../../../backend/app/services/edgar/circuit_breaker.py), which occur on the CLOSED→OPEN and HALF_OPEN→OPEN paths. The service can invoke it through [EDGAR compatibility/client calls](../../../backend/app/services/edgar/compat.py). Known job call paths are:

| Cloud Run job | Breaker path |
| --- | --- |
| `earningsnerd-pregenerate` | [`precompute_service.py`](../../../backend/app/services/precompute_service.py) searches companies and calls `get_filings`; summary document fetch can also enter the breaker. |
| `earningsnerd-filing-scan` | [`filing_scan_service.py`](../../../backend/app/services/filing_scan_service.py) calls `sec_edgar_service.get_filings`, which delegates to breaker-guarded EDGAR client methods. |
| `earningsnerd-backfill-facts` | Its optional `--backfill-company-sic` mode calls [`company_sic.py`](../../../backend/app/services/edgar/company_sic.py), which uses `run_with_circuit_breaker`. Its scheduled `--only-new` facts pass does not use this breaker. |

The SEC filter admits all `cloud_run_job` resources in this project, rather than these three names alone, because a job can be executed with a different `--args` script while retaining its resource label. The exact `sec_edgar` transition phrase prevents unrelated job failure logs from matching. The declared `earningsnerd-filing-digest` digest is database/email work; earnings-calendar refresh and notable-filings use EFTS calls without this breaker; earnings-day alerts and retention purge do not call it. These exclusions describe declared scripts, not a permanent guarantee about operator overrides.

Two attempted refutations of the generation gap failed: the original exception/timeout phrases do not match `Structured extraction error`, whose exception is converted into a returned `status=error`; and a successful Cloud Run job execution does not prove each drain succeeded, because `generate_summary_background` consumes terminal error events and `precompute_one` may classify from a persisted Summary row. Two attempted refutations of the SEC gap also failed: the breaker is not service-only because pregenerate and filing-scan invoke guarded EDGAR paths, and the all-jobs failed-execution metric reports a completed failure, not the process-local OPEN transition (which may be handled and followed by other work).

Remaining gaps are explicit. The service pipeline can yield terminal `error` on a 6-K with no retrievable text or on a no-sections `status=error` without a dedicated terminal log; no log filter can claim those outcomes from this source alone. An exception-free `generation_failed` classification with no retained Summary row is observable through the job error counter/failed-execution metric, not necessarily this log policy. SEC operations outside the shared breaker, such as EFTS and XBRL's plain-timeout primary path, do not produce a breaker transition. A live readback of natural log entries, severity, resource labels and alert delivery is still required before claiming measured coverage; no synthetic incident or production query was run for this receipt.
