# SEC outbound-attempt map — source audit 2026-09-21

Scope: backend `sec.gov`/EFTS calls, pinned `edgartools==5.58.0`. This is a code-path map, not wire telemetry. [`sec_rate_limiter.py`](../../../backend/app/services/sec_rate_limiter.py) grants a token before each `execute()` callback and before **each** `execute_with_backoff()` attempt; the latter retries rate-limit responses up to `SEC_MAX_RETRIES` (default 5) with bounded `Retry-After`. Its token bucket is per importing process. [`edgar/async_executor.py`](../../../backend/app/services/edgar/async_executor.py) wraps an entire SDK call, so its circuit breaker and timeout do **not** imply one limiter admission per SDK HTTP request. The SEC's per-IP cap is 10 requests/s; dynamic Cloud Run egress identity remains unobserved.

The SDK paths are the decisive residual. A future Slice B implementation must place admission at the SDK HTTP transport's *actual outbound attempt*, not merely before `EdgarCompany` construction or a high-level `get_filings` call. Instrument or mock the pinned SDK transport to count URL, method, timestamp, process, retry number and pagination shard **without storing filing contents, headers or identity secrets**. Demonstrate multi-process overlapping cold lists, an old-accession full-history fallback, SDK 429/5xx retries and direct-HTTP redirects. Every `sec.gov`/`efts.sec.gov` wire attempt must have its own unexpired grant; permit waits hold no DB connection. Then measure current egress IP domains, provider quota and live aggregate burst before choosing rate/burst/wait policy. The [E09 proposal](../../fleet-coordination-proposal-2026-09-19.md) separates conservative shared admission from a strict dispatcher. Neither is implemented or authorized here.

The existing [`sec.gov` import allowlist](../../../backend/tests/unit/test_sec_gov_importers_allowlist.py) checks URL-literal ownership, not dynamic routing through the SDK. No traffic test, provider call or fleet coordinator was run for this audit.
