# Summary request evidence v1

The authenticated `generate-stream` route emits consent-gated `summary_request_started` and
`summary_request_finished` observations. The existing pipeline and SSE payloads are unchanged.
These events measure the server's request outcome, not a browser view, useful output, provider
call count, billing charge or exactly-once analytics delivery.

Each server invocation creates a fresh `request_id`, including a cached serve, retry or rejection.
`account_id_at_event` and the PostHog distinct ID come from the authenticated account; a supplied
`ph_id` is accepted for compatibility and ignored. The event records `identity_evidence` as
`server_authenticated`. Later person merges must not replace that account snapshot.

The browser creates one random in-memory `logical_request_id` per `generateSummaryStream` call.
Automatic retries share that label; another user action gets another label. `client_attempt`
identifies the outer attempt and `transport_attempt` the initial handshake or auth-refresh replay.
These fields are client-supplied correlation hints, never authentication or idempotency keys.
Missing UUID support leaves logical identity unknown while allowing generation to work.
Group hints only within the same account and filing; retain conflicting groups as ambiguous.

Before **every** physical handshake the browser reads the existing analytics preference. Only an
affirmative preference sends the consent declaration and correlation fields. The route suppresses
both new request observations and its legacy pipeline funnel events without that declaration.
Consent granted or revoked after a request begins cannot retroactively change the request's
snapshot. `consent_evidence=client_declaration` makes this limitation explicit; the server has no
independent stored consent receipt. Other backend event families are outside this change.

## Outcomes and delivery paths

`summary_request_finished` has one of these observed outcomes:

| Outcome | Meaning |
| --- | --- |
| `complete` / `partial` | The server offered that terminal frame, with the returned `summary_id`. It does not prove browser receipt or usefulness. |
| `error` | The stream offered an error or the route/stream raised an unexpected exception. |
| `timed_out` | The pipeline's timeout handling offered its error frame; `reason=pipeline_timeout`. A provider deadline that produces usable fallback remains complete/partial as actually served. |
| `rejected` | The authenticated route rejected the request, such as 403, 404 or 429; `reason=http_<status>`. |
| `cancelled` | Task cancellation or generator closure occurred before a terminal observation. The server cannot distinguish every client disconnect from server shutdown. |
| `incomplete` | The iterator ended without a terminal frame. |

The first terminal wins. Closing a stream after its complete/partial/error frame does not emit a
second cancelled outcome. Cleanup closes the pipeline iterator and preserves its existing shielded
provider/reservation/semaphore release. Auth/validation failures before route invocation are outside
this observed denominator. A start without a finish (process loss, analytics loss, an unconsumed
response, or a window boundary) remains **unknown**, not failure or success.

`delivery_path` distinguishes `router_cache`, `pipeline_cache`, `coalesced`, `generation`, and
the earlier `route` / `pipeline` stages. A failed shared leader can cause a follower to become a
generator; its path then becomes `generation`. `summary_service_invoked` records whether that
request invoked the summary service, not whether a provider call reached the wire or incurred a
charge. A generation attempt may retain a better stored result or lose a concurrent save race;
the path does not claim that the returned content was newly generated by this request.

## Prospective readout

Use `evidence_version=1`, `identity_evidence=server_authenticated`, affirmative consent and the
frozen account roster/exclusions. Join starts and finishes by **server `request_id`**, retaining
event UUIDs. Deduplicate identical deliveries; exclude conflicting properties/outcomes as ambiguous.
Do not merge different accounts or filings through a reused client label. Report each outcome and
delivery path, missing starts, missing finishes, malformed events and unavailable data separately.
Measure duration only from valid paired requests. Never label missing telemetry as a non-user or
silently remove an eligible user from the cohort denominator.

Logical-action groups are an additional client-labelled view of observed requests. A 401 handshake,
failed connection or non-consenting retry may never appear here. A later completed attempt does not
erase earlier errors. These events cannot produce a complete browser retry census, exact cached-view
count, global provider cost or whole-cohort success rate. Historical `generation_*` counts remain
diagnostics; the new request pair is the lifecycle measurement contract.

Offline unit/consumer controls cover fresh and cached routes, server identity, unique request IDs,
shared generation, usage gates, timeout, generated error, premature end, cancellation, closure after
success, consent and automatic/auth retries. Locked stream/auth/background contracts remain intact.
Live PostHog receipt and a real consenting cohort still require their own evidence.
